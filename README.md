# pdca

基于 Apple 备忘录的「纸笔 → 数字」个人 PDCA 助手。

**当前状态：读取链路已跑通，写入尚未启用。**
（在你看过留档内容并确认解析正确之前，不会加任何写入逻辑。）

---

## 它是干什么的

你在 iPhone / Mac 的备忘录里，一天写一页当天清单；Mac mini 定时把它整理成
结构化待办、生成日报、把未完成项顺延到第二天，并推送到你手机。

设计上刻意守住一条线：**判断归你，整理归机器。**

| 谁做 | 做什么 |
|---|---|
| **你** | 决定每条是待办还是备忘（用标记）、决定时段、手动打钩完成 |
| **机器** | 拆行、识别标记、去重、留档、生成日报、顺延、推送 |

机器**不猜**你的意图。它只在两种情况开口问：同一时段有 ≥2 条（要排序）、
或一条待办没写时段（要归属）。

---

## 书写格式

在备忘录的 `logs` 文件夹里建一条，**标题就是日期**：

```
2026-10-02
- [ ] 1215 305重新编号
* 荷载按名称命名
@中午 勘察表盖章
@下午 跟进 竣工报验
明天要交电费
```

| 写法 | 含义 |
|---|---|
| `- [ ] xxx` | 待办，未完成 |
| `- [x] xxx` | 待办，已完成 |
| `* xxx` | 备忘（不进待办） |
| `@上午/@中午/@下午/@晚上/@明天 xxx` | 待办 + 时段 |
| 直接写一行 | 待办，时段未指定（**零符号，最高频情况最省力**） |
| `# xxx` | 元信息，跳过 |

**容忍的写法**（都实测过）：`–`/`—` 等智能标点替换的减号、`•` 项目符号、
中文全角冒号、`[ ]`/`[x]` 无列表符号、标记写在行尾。

## 用法

```bash
# 0. 自检：不需要备忘录权限，验证解析器与代码契约（28 项）
python3 src/selftest.py

# 1. 初始化：定位日志文件夹并记下它的 id（只需一次）
bash deploy/init.sh

# 2. 读取当天页 → 解析 → 留档（只读，不改你的备忘录）
python3 src/read_day.py                # 今天
python3 src/read_day.py 2026-10-02     # 指定日期
python3 src/read_day.py --print        # 只看结果不写留档

# 3. 顺延：把未完成事项带到次日页（默认只干跑，不写入）
python3 src/carry_over.py 2026-10-02            # 干跑：只看计划写什么
python3 src/carry_over.py 2026-10-02 --offline  # 不查备忘录，纯离线验证计划
python3 src/carry_over.py 2026-10-02 --apply    # 真正写入

# 4. 日报：汇总当天并推送（默认读留档，--refresh 先从备忘录重读）
python3 src/daily_report.py --refresh        # 生成并推送
python3 src/daily_report.py --no-push        # 只看内容，不推送

# 5. 装成定时任务（21:30 日报 + 07:00 顺延）
bash deploy/install_launchd.sh install
bash deploy/install_launchd.sh test          # 验证链路（**不写入备忘录**）
bash deploy/install_launchd.sh test --write  # 只在需要验证写入链路时用（会改备忘录）

# 删掉误建的某天页面（精确匹配标题，多一个字都不删）
bash deploy/delete-day.sh --title 2026-10-03

# 查看备忘录访问状态
python3 src/notes.py verify
python3 src/notes.py list

# 离线测试解析器（不碰备忘录）
python3 src/parse.py 某个文件.txt
```

留档写在 `data/days/<日期>.md`（人可读、可手工修正）和 `<日期>.json`（机器读）。

## 为什么这样做（探测得出的硬约束）

这些都是实测结论，不是推测。每一条都对应代码里的一处设计。

### 1. 必须用文件夹 id 定位，不能用名字
你新建的日志文件夹曾叫 `Note`，而系统原本就有 `Notes`（21 条真实笔记），
两个名字只差一个字母。配置里存的是文件夹 **id**，所以改名不影响，
将来出现同名文件夹也不会选错。`deploy/init.sh` 在按名字查找时**要求唯一匹配**，
撞车就报错让你裁决。

### 2. 必须限定文件夹，绝不能用全局 `every note`
删除的备忘录会进「Recently Deleted」并保留 30 天，而 `count of notes` 与
`every note` **仍然会返回它，且它排在第一位**。如果按"第一条最新"读当天页，
会读到一条已删除的僵尸笔记并把它顺延到明天 —— **错得看不出来**。
所以所有查询都带 `of folder id "..."`。

### 3. 写入必须读回验证
备忘录存在「命令不报错但什么都没做」的静默失败。只看有没有抛错会把失败当成功。

### 4. 分行必须用 `<div>` 包每一行
直接把多行字符串交给备忘录会被**折叠成一行**
（`标题 - [ ] 甲 - [x] 乙 * 丙`），既难读也无法按行解析。

### 5. 走 `osascript` 子进程，而不是让程序自己操作备忘录
TCC 授权绑定调用进程身份。`osascript` 用的是**终端**的授权，稳定不变；
而做成 app bundle 时，ad-hoc 签名每次重新编译哈希都会变，授权随之失效，
需要反复重新授权。

### 6. 疑似重复只报告，绝不自动删
相似度高不等于重复（"提交结算单A"和"提交结算单B"可能是两件事）。
静默去重会丢数据，而丢数据是看不出来的。程序只列出来让你决定。

### 7. 顺延标记 `⟳` 让去重变复杂 —— 必须剥掉再比较
次日页里存的是「甲 ⟳」，而来源是「甲」，直接比较归一化结果**不相等**，
于是同一条被顺延了第二遍，幂等性失效。所以去重键要先剥掉 `⟳` 再归一化。
这个 bug 是在离线测试里发现的 —— 它证明了「能离线验证的逻辑就该离线验证」。

### 8. 写与读分成两个任务
`21:30 report` 只读 + 推送；`07:00 carryover` 是**唯一**会写备忘录的任务。
分开的好处：写入路径只有一个入口，出问题时排查面小得多。

### 9. 留档独立于备忘录
备忘录是书写界面，不是数据库。它可能因授权失效、iCloud 不同步、误删而读不到。
每天一份独立副本，出问题时你能看见丢了什么。

## ⚠️ 踩了三次的坑：bash 3.2 + 全角字符

macOS 自带的 bash 3.2 会把**全角字符的字节**当成变量名的一部分：

```bash
echo "删除当天页：「$TARGET」"
# → TARGET?: unbound variable
#   报错信息还把变量名截断成 "TARGET?"，看不出真相
```

`」` 紧跟 `$TARGET`，bash 就去寻找名为 `TARGET」` 的变量，于是 `set -u` 报未定义。

这个坑在本项目里出现了三次（两个探测脚本 + `delete-day.sh`），第三次才用
`bash -x` 追踪看清楚真面目 —— 前两次我都误判成"命令替换里的变量问题"。

**修法**：凡是 `$VAR` 后面要跟中文/全角标点，一律写 `${VAR}`。
`src/selftest.py` 里固化了检查，会扫描 `deploy/*.sh` 并报告这类写法。

## ⚠️ 一次真实事故：验证命令写入了数据

安装完定时任务后，我让你跑 `install_launchd.sh test` 验证链路。当时的
`test` 实现是无差别 `kickstart` 两个任务 —— 而顺延任务带 `--apply`，
于是它**立即新建了「次日页」（2026-10-03）**，可 10-02 当天还没过完。

后果不是数据损坏，而是**顺延清单基于不完整状态**：当晚你若再打钩完成某项，
那条已经被写进次日页了，不会被撤回。

两处修正：

1. `test` 默认**不产生副作用**：手动以干跑方式跑一遍（只读 + 计划预览），
   只有显式 `--write` 才通过 kickstart 触发真实的写入任务。
2. 新增 `deploy/delete-day.sh` 用于精确删除误建的页面
   （用 `is` 精确匹配标题，不是 `contains`/`starts with`）。

教训：**"看似无害的检查"也可能有真实副作用**。凡是会写用户数据的任务，
验证入口必须默认安全。

## 目录

```
pdca/
├── config.json          日志文件夹的 id（init.sh 生成，已 gitignore）
├── src/
│   ├── notes.py         备忘录访问（限定文件夹、id 定位、读回验证）
│   ├── parse.py         解析器（纯函数，可离线测试）
│   ├── sync.py          读取 → 解析 → 留档（三处共用的同步步骤）
│   ├── notify.py        Bark 推送（复用 ltc-spider 的 key，不复制密钥）
│   ├── read_day.py      手动读取某天
│   ├── carry_over.py    顺延（默认干跑，--apply 才写入）
│   ├── daily_report.py  日报 + 推送
│   └── selftest.py      39 项离线自检（含静态契约检查）
├── deploy/
│   ├── init.sh          初始化：定位文件夹、记下 id
│   ├── install_launchd.sh   定时任务安装（install/status/test/reload）
│   ├── com.carl.pdca.*.plist
│   └── probe-*.sh       能力探测脚本（历史存档，见 docs）
├── docs/
│   ├── CONCEPT.md       概念澄清：这件事到底要做什么
│   └── ORIENTATION-ROOTCAUSE.md   方向问题的根因分析（另有用途）
└── data/days/           留档（已 gitignore）
```
