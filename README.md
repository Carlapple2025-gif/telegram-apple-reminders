# pdca

基于 Apple 备忘录的「纸笔 → 数字」个人 PDCA 助手。

**当前状态：读取链路已跑通，写入尚未启用。**
（在你看过留档内容并确认解析正确之前，不会加任何写入逻辑。）

---

## 它是干什么的

你在 iPhone / Mac 的备忘录里，一天写一页当天清单；Mac mini 定时把它整理成
结构化待办、生成日报、把未完成项顺延到第二天，并推送到你手机。

设计上刻意守住一条线：**判断归你，整理归机器。**

| 谁做 | 做什么 |
|---|---|
| **你** | 决定每条是待办还是备忘（用标记）、决定时段、手动打钩完成 |
| **机器** | 拆行、识别标记、去重、留档、生成日报、顺延、推送 |

机器**不猜**你的意图。它只在两种情况开口问：同一时段有 ≥2 条（要排序）、
或一条待办没写时段（要归属）。

## 书写格式

在备忘录的 `logs` 文件夹里建一条，**标题就是日期**：

```
2026-10-02
- [ ] 1215 305重新编号
* 荷载按名称命名
@中午 勘察表盖章
@下午 跟进 竣工报验
明天要交电费
```

| 写法 | 含义 |
|---|---|
| `- [ ] xxx` | 待办，未完成 |
| `- [x] xxx` | 待办，已完成 |
| `* xxx` | 备忘（不进待办） |
| `@上午/@中午/@下午/@晚上/@明天 xxx` | 待办 + 时段 |
| 直接写一行 | 待办，时段未指定（**零符号，最高频情况最省力**） |
| `# xxx` | 元信息，跳过 |

**容忍的写法**（都实测过）：`–`/`—` 等智能标点替换的减号、`•` 项目符号、
中文全角冒号、`[ ]`/`[x]` 无列表符号、标记写在行尾。

## 用法

```bash
# 0. 自检：不需要备忘录权限，验证解析器与代码契约（28 项）
python3 src/selftest.py

# 1. 初始化：定位日志文件夹并记下它的 id（只需一次）
bash deploy/init.sh

# 2. 读取当天页 → 解析 → 留档（只读，不改你的备忘录）
python3 src/read_day.py                # 今天
python3 src/read_day.py 2026-10-02     # 指定日期
python3 src/read_day.py --print        # 只看结果不写留档

# 查看备忘录访问状态
python3 src/notes.py verify
python3 src/notes.py list

# 离线测试解析器（不碰备忘录）
python3 src/parse.py 某个文件.txt
```

留档写在 `data/days/<日期>.md`（人可读、可手工修正）和 `<日期>.json`（机器读）。

## 为什么这样做（探测得出的硬约束）

这些都是实测结论，不是推测。每一条都对应代码里的一处设计。

### 1. 必须用文件夹 id 定位，不能用名字
你新建的日志文件夹曾叫 `Note`，而系统原本就有 `Notes`（21 条真实笔记），
两个名字只差一个字母。配置里存的是文件夹 **id**，所以改名不影响，
将来出现同名文件夹也不会选错。`deploy/init.sh` 在按名字查找时**要求唯一匹配**，
撞车就报错让你裁决。

### 2. 必须限定文件夹，绝不能用全局 `every note`
删除的备忘录会进「Recently Deleted」并保留 30 天，而 `count of notes` 与
`every note` **仍然会返回它，且它排在第一位**。如果按"第一条最新"读当天页，
会读到一条已删除的僵尸笔记并把它顺延到明天 —— **错得看不出来**。
所以所有查询都带 `of folder id "..."`。

### 3. 写入必须读回验证
备忘录存在「命令不报错但什么都没做」的静默失败。只看有没有抛错会把失败当成功。

### 4. 分行必须用 `<div>` 包每一行
直接把多行字符串交给备忘录会被**折叠成一行**
（`标题 - [ ] 甲 - [x] 乙 * 丙`），既难读也无法按行解析。

### 5. 走 `osascript` 子进程，而不是让程序自己操作备忘录
TCC 授权绑定调用进程身份。`osascript` 用的是**终端**的授权，稳定不变；
而做成 app bundle 时，ad-hoc 签名每次重新编译哈希都会变，授权随之失效，
需要反复重新授权。

### 6. 疑似重复只报告，绝不自动删
相似度高不等于重复（"提交结算单A"和"提交结算单B"可能是两件事）。
静默去重会丢数据，而丢数据是看不出来的。程序只列出来让你决定。

### 7. 留档独立于备忘录
备忘录是书写界面，不是数据库。它可能因授权失效、iCloud 不同步、误删而读不到。
每天一份独立副本，出问题时你能看见丢了什么。

## 目录

```
pdca/
├── config.json          日志文件夹的 id（init.sh 生成，已 gitignore）
├── src/
│   ├── notes.py         备忘录访问（限定文件夹、id 定位、读回验证）
│   ├── parse.py         解析器（纯函数，可离线测试）
│   └── read_day.py      读取 → 解析 → 留档
├── deploy/
│   ├── init.sh          初始化：定位文件夹、记下 id
│   └── probe-*.sh       能力探测脚本（历史存档，见 docs）
├── docs/
│   ├── CONCEPT.md       概念澄清：这件事到底要做什么
│   └── ORIENTATION-ROOTCAUSE.md   方向问题的根因分析（另有用途）
└── data/days/           留档（已 gitignore）
```
