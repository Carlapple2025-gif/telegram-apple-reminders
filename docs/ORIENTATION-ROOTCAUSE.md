# 方向之谜：为什么一张"看着是正的"照片，模型读出来是乱的

这篇记录的是一次真实调试：为了把 iPhone 拍的手写清单喂给视觉模型，我在"要不要旋转图片"这件事上连续得出过三个互相矛盾的结论，最后才找到真正的原因。

写下来是因为**这个坑极难自查** —— 每个人（包括我自己）用的验证方法本身就会给出假象。

---

## 现象

- `list.jpg`（iPhone 竖拍的纸笔清单）
- 用 Finder / 预览 / 任何看图工具打开：**文字正立，清晰可读**
- 但直接把这些像素送给视觉模型：识别结果是**纯幻觉**
  （"1215 305 更换压缩机 / 叶 散热器 蒸发器" —— 而纸上写的是"1215 305重新编号"）

## 三个互相矛盾的结论

| # | 我的结论 | 依据 | 为什么错 |
|---|---|---|---|
| 1 | 需要**顺时针 90°** | 旧记录里写过，且"iPhone 竖拍像素是横的"是常识 | 结论本身对，但我没验证 `sips` 的行为 |
| 2 | 需要**0°（不转）** | 人眼直读 `list.jpg` → 文字正立；墨迹分布分析也说正立 | **验证方法有假象**：看图工具会自动应用 EXIF，我看到的"正立"是工具帮我转过的 |
| 3 | 需要**180°** | 墨迹行向粗糙度打分 | 那个判据只能区分横竖，**不能区分正倒** |

## 真正的根因：两个"90°"叠加了

事实是这样的：

```
存储的像素：4032×3024（横）
EXIF orientation = 6  →  含义："显示时顺时针转 90°"
```

于是：

| 谁 | 看到的朝向 |
|---|---|
| Finder / 预览 / 看图工具 | 应用 EXIF → **竖版、文字正立** ✅ |
| 视觉模型 API | **不解析 EXIF** → 拿到横版原始像素、文字侧躺 ❌ |

而我用的 `sips` 属于**前者** —— 它计算旋转时会把 EXIF 算进去，基准是"人眼所见的朝向"，不是文件里的像素。所以：

```
带 EXIF=6 的文件  sips -r 90   →  在"已转正"的基础上再转 90°  →  横躺  ❌
带 EXIF=6 的文件  sips -r 180  →  在"已转正"的基础上转 180°   →  倒置  ❌
带 EXIF=6 的文件  不做旋转      →  与预览一致、正立             ✅（但只是"人看着对"）
```

**三种都试过，三种都不能让模型看到正确的图** —— 因为无论怎么转，EXIF 标记还在，模型始终看原始像素。

## 解法：三步，顺序不能换

```
① 纯 Python 剥掉 EXIF 段（APP1）      ← 让 sips 的基准变成"像素本身"
② sips -r 90 物理旋转像素             ← 现在 90° 就真的是 90°
③ 缩放（长边 2200）
```

验证结果：

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 输出像素尺寸 | 2200×1650（横） | **1650×2200（竖）** |
| 输出 EXIF orientation | 6（模型不认） | **无** |
| 人眼直读 | 正立（假象） | 正立（真实） |
| 模型看到 | 横躺 → 幻觉 | **竖版正立** |

## 四条可迁移的教训

1. **"我看着是对的" ≠ "对方收到的是对的"**
   EXIF 方向让同一份文件在不同程序里呈现不同朝向。判断"模型看到了什么"，
   必须看**原始像素**，不能看渲染结果。

2. **验证工具会引入假象，而且不报错**
   我用看图工具验证了三次，每次都"证实"了错误结论。工具不会告诉你它悄悄转了图。

3. **元数据与像素冲突时，以接收方为准**
   EXIF 说该转 90°，像素本身却是正的（人眼所见）。这不是矛盾，是"给谁看"的问题 ——
   模型只认像素。

4. **转错比失败更危险**
   方向错会得到一段**看起来合理、语义完全错误**的结果（"复工报检" vs "竣工报验"，
   "3楼" vs "386"）。所以未知 orientation 时选择**拒绝处理并告警**，
   而不是猜一个方向继续。

## 附：怎么快速自查方向

```bash
# 看 EXIF 标记（决定"显示朝向"）
python3 scan_inbox.py --debug-exif 照片.jpg

# 看原始像素尺寸（决定"像素朝向"）—— 注意 sips 报的是像素，不是显示尺寸
file 照片.jpg | grep -oE '[0-9]+x[0-9]+'

# 剥掉 EXIF 后再转，然后人眼确认
# （这是唯一可信的确认方式：把 EXIF 拿掉，剩下的朝向就是模型看到的）
```

判据：**像素尺寸与"人眼所见"的宽高比不一致时**，说明存在 EXIF 方向标记，
必须走上面三步。
