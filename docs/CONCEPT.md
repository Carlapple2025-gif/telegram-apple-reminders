# 概念澄清：你要的到底是什么

这份文档回答的是「把模糊概念进一步清晰化」。所有结论都来自三处**实证**，不是推测：

1. 你放进来的 3 个 DSH 会话导出（8 个会话、约 14,000 条事件）；
2. 会话里记录的标准答案（你亲手纠正过的识别结果）；
3. 我在**这台 Mac mini 上**刚刚实测到的现状。

---

## 一、先纠正一个关键误解（包括我自己）

我此前把这件事理解成「做一个查提醒/日程/备忘录的助手」，于是先做了 `apple-assistant`（EventKit 读写三件套 + 手机控制台）。方向不算错，但**漏掉了你整套设计的重心**。

从记录看，你真实的体系是这样的：

```
┌─ Plan / Do 的真实发生地 ────────────────────────┐
│  纸笔。每天早上八九点，手写今天的清单。            │
│  （这是你唯一稳定运行的习惯，不该被替代）          │
└──────────────────────────────────────────────┘
              ↓ 拍一张（1 秒，习惯零改动）
┌─ 采集通道 ───────────────────────────────────┐
│  iPhone 快捷指令/手动 → iCloud 容器 → Mac mini  │
└──────────────────────────────────────────────┘
              ↓
┌─ Mac mini：识别与归档 ───────────────────────┐
│  转正 → 视觉模型 → 结构化清单 → 留档 + 推送      │
│  （实测 96~100% 逐字准确率）                    │
└──────────────────────────────────────────────┘
              ↓
┌─ Check / Act：数字镜像 ──────────────────────┐
│  Reminders 承载 Plan/Do、Notes 承载 Check/Act   │
│  晚间语音复盘 + 日报/周报                       │
└──────────────────────────────────────────────┘
```

**核心澄清**：数据源不是「提醒事项 App」，而是**纸笔 + 照片**。Reminders 是镜像，不是源头。

## 二、你自己的记录里已经沉淀的硬结论

这些是**已经付过学费**的结论，不该重新踩一遍：

| 结论 | 证据 | 影响 |
|---|---|---|
| **纸笔不要动** | 你「每天早上八九点手写清单」是已养成的习惯，也是最难的那一步 | 任何要求你改用 App 记事的方案都会死在替代成本上 |
| **记录方式目前是「突发式」** | 探针读数：3 个月 7 条、45 天没新增、近 14 天完成 0 条 | 所以不能让采集依赖「你会去用某个 App」 |
| **Apple 系统 OCR 读不了你的字** | 原图/旋转/裁切放大/换格式，四次测试全部返回空 | 拍照路线**必须**走视觉模型，不能走系统 OCR |
| **视觉模型能读，且很准** | 两天成绩单：9/17 全对（25/25）、9/18 一处连笔字错（22/23） | 路线可行；唯一稳定错误类型是**行首连笔的时间词**（"中午"被读成"竹/村/出"） |
| **模型有时比人准** | 三次模型胜过直读：存证/佐证、勘察表/勘测表、中午/杆 | 但「模型不确定」≠「模型会错」，不能靠它的自我报告判断 |
| **提示词加领域词汇是负优化** | 加了光伏/时间词提示后成本涨 10 倍（570→6030 token），错误照旧 | 保持简洁提示词 |
| **方向处理是最大的技术坑** | EXIF 与像素朝向不一致，见 [`ORIENTATION-ROOTCAUSE.md`](ORIENTATION-ROOTCAUSE.md) | 必须「剥 EXIF → 物理旋转」，否则模型看到横躺的图 |
| **iCloud 文件可能是"占位"** | `SF_DATALESS` 标志 + 读太早报 `EDEADLK` | 要重试 + `brctl download`，且单文件失败不能拖垮整批 |
| **真无人值守需要「有权限 + 常在 + 能算」** | iPhone 后台受限、笔记本合盖就断（实测挂死 5.5 小时并堵住第二天） | 三列全绿的只有 Mac mini |

## 三、Mac mini 的作用（精确版）

不是笼统的"服务器"，而是三个**具体且已验证**的职责：

| 职责 | 为什么只有它能做 |
|---|---|
| **定时吃照片** | 你的流程是「拍一张就不管」。要有一个常在的节点去发现新照片、调模型、写回结果 |
| **一次授权长期有效** | 读 Reminders 需要 TCC 授权；笔记本上随系统升级/换机就会失效（记录里已发生过一次） |
| **算与存档** | 手写清单本身只是文本。周报、趋势、连续天数、"哪类事总做不完"需要能常开跑脚本的机器 |
| **失败可诊断** | 可把失败日志交给 headless 智能体先定位（思路来自你上次分享的那篇文章），只在它搞不定时才推给你 |

**一条关键判断**：真正需要 Mac mini 的不是「读数据」（那可以用文件路线绕开授权），而是**「每天固定时间、无人干预地把结果算出来并推给你」** —— 也就是 PDCA 里最容易被放弃的 C 和 A。

## 五、清晰化后的产品定义

> **一句话**：Mac mini 上的「纸笔 → 数字」自动化助手 —— 早上自动把手写清单变成结构化待办并推回手机，晚上自动汇总成 PDCA 日报，全程不需要你多做一个动作。

### 三个功能，优先级明确

| 优先级 | 功能 | 触发 | 产出 |
|---|---|---|---|
| **P0** | 清单识别 | 每天 12:00 / 20:00 扫描 inbox | 结构化清单 + 留档 + 推送到手机（**含手动纠错入口**） |
| **P0** | 数据新鲜度告警 | 每次生成时 | 摘要**必须带数据截止时间**，陈旧就明确告警 —— 不能静静输出旧数据 |
| **P1** | 日报 / 周报 | 每天 22:30 / 周日 20:00 | 完成率、连续天数、常见未完成原因 |
| **P2** | 写回 Reminders | 识别后 | 让锁屏小组件可以打勾（Do 环节数字化） |
| **P3** | 智能体诊断 | 任务失败时 | `dsh --profile headless` 先定位，搞不定才推给你 |

### 三个必须坚持的原则

1. **纸笔零改动** —— 你的流程不能因为自动化而多一步
2. **宁可报错，不可静默** —— 没权限、文件没同步、识别失败，都要明确说出来。
   「今天没有安排」和「我没读到你的数据」是两件完全不同的事，绝不能长得一样
3. **确认环节先留着** —— 96% 不等于 100%，而现有错误恰好都是**会改变语义**的那类
   （"竣工报验"↔"复工报检"、"3楼"↔"386"）。等样本够了再谈去掉

## 六、两个架构选择点（需要你定）

### 选择点 1：写回 Reminders 走哪条路？

| | A. 文件快照路线 | B. EventKit 直读路线 |
|---|---|---|
| 原理 | 快捷指令把 Reminders 快照写成文件，Mac mini 只读普通文件 | Mac mini 直接读写 Reminders |
| 需要授权 | ❌ **完全不需要**（读普通文件不触发 TCC） | ✅ 需要一次性 TCC 授权 |
| 换机/升级后 | 不受影响 | 授权可能失效，要重做 |
| 数据实时性 | 有延迟 | 实时 |
| 已建好 | `apple-assistant` 已支持文件读取的概念 | `apple-assistant` 的 EventKit 源已写完并自检通过 |

**我的建议：A 打底、B 作增强** —— 先让整条链路在零授权下闭环，授权后再加上实时读写。

### 选择点 2：代码放哪？

| | A. 并入工作区（如 `pdca/`）+ 独立 git | B. 回到 `~/.pdca/` |
|---|---|---|
| 与工作项目隔离 | 独立仓库，但同机同工作区 | 物理隔离 |
| 迁移/备份 | 跟着工作区一起走，不容易再丢 | **上次就是这样丢的** |
| 智能体可维护 | ✅ 在工作区内，我能直接读写 | ⚠️ 工作区外，每次写入要你授权 |
| 隐私 | 与 ltc-spider 同工作区 | 更干净 |

**我的建议：A** —— 上次的教训就是"放在工作区外 → 没迁移 → 丢失"。隔离用**独立 git 仓库**实现就够了，不必用文件系统位置来隔离。

**还差一步才能真正跑通识别**：一个视觉模型的 API key。记录里确认过：

- 必须是 `deepseek-flash`（`deepseek-v4-pro` 会返回 `Unsupported Image`）
- `max_tokens` 必须 ≥2000（思考 token 会吃光预算，`content` 会**静默返回空**）
- 图片只能放在 user 消息里

我没有这把 key（DSH 自己持有，未导出到环境变量）。你按记录里的方式提供即可：

```bash
mkdir -p ~/.pdca && echo 'DEEPSEEK_API_KEY=sk-你的key' > ~/.pdca/.env && chmod 600 ~/.pdca/.env
```

（我的脚本会从 `~/.pdca/.env` 或项目内 `.env` 读取，不会把 key 写进任何提交。）
