# 节奏与载体（CADENCE）

> **状态：设计已定（2026-10-10），尚未实施。**
> 这份文档是 2026-10-08 ~ 10-10 几轮讨论的收敛点，只回答一个问题：
> **什么东西住在哪个 App，由谁在什么节奏上看。**
>
> 它**不改输入语言**（新符号 = 0），见 §十一。

---

## 一、目标函数：不是"待办清空"，是"标准提高"

系统服务的对象是**习惯**，而习惯的本质是**自动化的标准作业**（用户原话）。

| | 干什么 | 例子 |
|---|---|---|
| **PDCA** | **提高**标准 | 0 次 → 1 次 → 3 次 |
| **SDCA** | **稳定**标准 | 把 3 次守住，直到不用想就做 |

所以系统的输出不该是"你还有几件事没做"，而是**"标准守住了没有、要不要动它"**。

## 二、通则（一句话，所有边界问题都由它回答）

> ## 要打钩的放提醒事项，要守 / 要看的放日历。

| 类别 | 放哪 | 为什么 |
|---|---|---|
| 承诺（待办）| 提醒事项 | 只有它有**完成态** |
| 节律（习惯 = 标准作业）| 提醒事项（**重复条目**）| 需要"每次打钩" |
| 目标 / 里程碑 | 日历 | **没有完成态恰恰是对的** —— 目标是"看"的，不是"打钩"的 |
| 外部约束（截止 / 会议 / 出差）| 日历 | 时间不可协商，别人也在场 |
| 流水账（想法 / 记录）| 备忘录 | 不进循环；它的去处是"每月看模式" |

## 三、三条轴（互不干扰）

| 轴 | 由谁承担 | 回答 |
|---|---|---|
| **时间** | 日历 | 什么时候 |
| **类别** | **住哪个 App**（结构事实，不靠标签、不靠猜）| 承诺 / 节律 / 目标 / 流水账 |
| **域** | 日历名、提醒列表名 | 工作 / 私人 |

分类**与日历无关** —— 日历只承载时间。但"域"仍需要一个零成本的落点：
日历名（iCloud「个人」/「工作」）。

## 四、日历的成员：只有四类

| 类型 | 例子 | 能不能动 |
|---|---|---|
| **外部约束** | 10-15 交 10 份材料（有人等着）| **不能动** |
| **目标里程碑** | 11-10 出线条 | 可移，但要留痕 |
| **一次性事务** | 去龙井村 | 可移 |
| **时间预算区块** | `⛺ 突击：10 份材料 14:00–18:00` | 你自己留的 |

**为什么习惯不在这里**（2026-10-10 裁决）：

1. 日历事件**没有完成态**（APPLE-FACTS §2.2）→ 检查不了；
2. 日复一日的重复条目会**糊住月视图的日期数字**，让注意力失焦；
3. "重复"本身不脏 —— **"别人也在场的固定时间点"（周会、值班）保留重复** ✓，
   脏的是"自己要打钩的行为"。

**前缀约定**：时间预算区块用 `⛺` 开头 —— 这是**声明**，不是猜，机器和你都能一眼认出。

## 五、提醒事项的成员

| 类型 | 形态 | 说明 |
|---|---|---|
| 承诺 | 普通待办（带到期日）| 现有行为不变 |
| **节律 / 标准作业** | **重复条目**（人工建一次）| 每次完成都会留下一条完成记录 |
| **两档标准** | 两条重复提醒（正常 / 最低）| 打钩哪条 = 声明今天用了哪档 |

**为什么必须两档**：习惯死掉从来不是因为做得少，是因为**断了一次就再也没接上**。
最低档（2 个俯卧撑）用于出差 / 应酬 / 生病 —— 它的作用是**不中断**。

## 六、PDCA 与 SDCA 的四条操作规则

1. **PDCA 生产标准，SDCA 消费标准** —— PDCA 的产物就是一个可执行的标准；
2. **稳定才提高**（SDCA 守住 2–4 周，才进下一轮 PDCA）—— 没守住就提高必然崩；
3. **一次只改一件事，且只在周报里改** —— 否则分不清是哪个改动起了作用；
4. **连续失败 = 标准定错了，不是你的问题** → 降一档，而不是自责。

## 七、三个节奏

**日（C：只看差异）**

```
🎯 标准 vs 实际     ← 打钩数据（来自提醒事项）
　　8:35 检查待办  ✅ 连续 12 天（稳定）
　　20:30 英语     ✅ 本周 5/5（稳定）
　　力量训练        ⚠️ 本周 1/3（建立中，正常档/最低档分开算）
⏳ 承诺：只列**超过你标准**的（放了 4 天还没动）
📅 倒计时          ← **日历给日报的基线**：距 10-15 交材料还有 5 天
❓ 今天需要你决定 1 件（最多 1 件）
```

**周（P：唯一需要你输入的时刻）**

```
① 下周什么节奏？（正常 / 出差 / 假期 / 生病）  ← 这一句决定"标准"这把尺子
② 三个标准要不要动？（英语 5→6？力量训练 3 起？）
③ 本周挑 3 件承诺
④ 策略：均摊还是突击（见 §八）
```

**月（A：看模式）**

- **目标进度**（月度看 —— 目标是慢循环，日报不碰它）；
- **策略复盘**（均摊失败了几次？→ 换突击）；
- **流水账**（备忘里反复出现的主题 → 该立成承诺了；几周没动的 → 删掉也是决定）。

## 八、均摊 vs 突击：策略**不单独存储**

策略体现在**"标准长什么样"**里：

| 策略 | 表达方式 |
|---|---|
| **均摊** | 一条**重复提醒**（每天 1 份材料）|
| **突击** | 日历上的**时间预算区块**（10-14 14:00–18:00）|

经验法则（**是经验，不是定律**）：

- **需要持续投入的**（写作、健身、语言）→ 均摊（能力靠积累）；
- **可批量的机械活**（10 份材料、报税、整理）→ 突击（切换成本才是主要损耗）；
- ⚠️ 突击的隐藏成本：**依赖"那天真的有空"** → 所以必须预留区块，
  否则事后分不清是"策略错"还是"那天被占了"。

## 九、留档（这条是老设计，现在有了新用途）

**Apple 里的完成记录会被清空**（你在 App 里点一下"清除已完成"就没了）。
所以：**journal 必须自己留一份** —— 周 / 月的达成率只能从这里算。

这正是 ARCHITECTURE 里那条"**留档独立于 Apple 应用**"的第二个用途。

## 十、边界（不做什么）

- ✗ **不猜意图** —— 标准、目标、节奏全部由你声明；
- ✗ **不替你决定** —— 日报每天最多列 1 件"需要你决定"，选项给全，不自作主张；
- ✗ **不指导专业内容** —— 系统不告诉你该练什么动作（那是训练知识）；
- ✗ **不新增每天必填的输入** —— 摩擦 = 会断；P 只在**周**，而且可以一句话。

## 十一、成本（按 KERNEL-CONTRACT §六 判）

| | 结论 |
|---|---|
| 输入语言（符号表）| **不动** —— 新符号 0 个 |
| 落点契约 | **不动** —— 待办仍落默认列表，日程仍落「个人」|
| journal schema | 需要**加字段**（完成记录），向后兼容 |
| 版本影响 | 全程 **MINOR**，**不碰 MAJOR** |

**为什么不需要新符号**：

| 要表达的东西 | 它住在哪 | 需要新输入吗 |
|---|---|---|
| 标准 | 提醒事项的重复条目 | ❌ 数据本来就在 App 里 |
| 策略 | 不需要单独存（体现在标准长什么样）| ❌ |
| 目标 | 日历上一条全天事件（现有 `@` 就行）| ❌ |
| 两档 | 两条重复提醒 | ❌ |

## 十二、前提：必须先验证的三件事（探针）

写在 [`tools/probe-reminders-history.py`](../tools/probe-reminders-history.py)，**只读**：

| # | 要验证的 | 影响 |
|---|---|---|
| ① | 已完成条目是否留下、有没有 `completion date` | 决定周/月达成率算不算得出来 |
| ② | AppleScript 能否按 `completed` **原生筛**（而不是全表读回 Python 筛）| 决定读取代价（日历那边踩过全表扫描的坑）|
| ③ | 一条重复提醒完成后，是**生成新的一条**还是覆盖原条 | 决定"一周 5/7"这种统计能不能做 |

**③ 需要你先手工建一条重复提醒，几天后再跑一次** —— 探针一次跑不完。

> 在 ①②③ 拿到实测证据之前，§四 / §五 的载体调整都只是**待验证的设计**，
> 不要按它去改代码。

## 十三、实施顺序（每阶段带一道闸门）

| 阶段 | 谁做 | 内容 | 闸门 |
|---|---|---|---|
| 0 | 我 | 探针（①②），①②③的判断依据 | 有实测证据 |
| 0.5 | 我 | 本文档 | 你读完说"就是这样" |
| 1 | 你 | **只搬一个习惯**（建议 20:30 英语）→ 建正常/最低两条重复提醒 | 能连续打钩 5 天 |
| 2 | 我 | 读完成态 → 写进 journal | 数据与 App 一致 |
| 3 | 我 | 日报改 C（差异 + 倒计时 + 最多一个决定）| **你读完做过决定** |
| 4 | 我 | 周报改 P / 新建月报 | 跑满一个月 |

**为什么"只搬一个"**：一次改一件事。搬三个都没坚持住，就分不清是标准太大还是设计有问题。
