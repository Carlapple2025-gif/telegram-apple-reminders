## 一、什么是"公开 API"

**不是 Python 函数签名** —— 这个项目没有第三方调用者，函数随时可以改。
"公开 API"指的是**三层对外契约**（对外 = 对你、对已写下的数据）：

| 层 | 内容 | 破坏它就进 MAJOR（第 1 位） |
|---|---|---|
| ① **输入语言** | 行首声明：`#` 备忘 / `@` 日程 / 裸输入待办 / `/` 命令 | 增删符号、改符号语义、**改默认落点** |
| ② **落点契约** | 同一条输入写进哪个 App、`journal` 记哪个事件 | 落点变了、事件名或字段语义变了 |
| ③ **内核 ABI** | `kinds.Item` 的字段含义 + §二 的模块边界 | 改字段语义、删字段、越界（§三 白名单之外） |

**为什么把这三层叫"公开"**：因为它们各自都有一个**你无法同时升级的另一端** ——
① 的另一端是你的输入习惯，② 的另一端是 Apple 应用里的既成事实，
③ 的另一端是 journal 里**已经写下的、不可再生的**读数。

## 二、模块分类（全量、不重不漏）

| 类 | 模块 | 规则 |
|---|---|---|
| **内核**（12） | `telegram` `journal` `whens` `kinds` `parse` `routes` `intake` `notify` `reminders` `applecal` `memo` `daemon` | **不得 import 功能模块**（白名单例外见 §三） |
| **功能**（3） | `report`（日报） `commands`（命令） `watchdog`（看门狗） | **不得 import 另一个功能模块** |
| **遗留**（11） | `carry_over` `cleanup` `cleanup_reminders` `completion` `daily_report` `notes` `probe_reminders` `push_tasks` `read_day` `reconcile` `sync` | v1 的，v4 不接线；改它们不需要动契约 |
| **工具**（1） | `selftest` | 测试宿主，不参与运行时 |

自检断言**"每个 `src/*.py` 恰好属于一类"** ——
所以**新模块忘了登记会直接变红**（这是本项目"手工名单"第一次变成全量划分，
以前那几张名单（`:674` / `:3145` / `:1195`）漏登记是没有后果的）。

## 三、越界白名单（4 条，**只许缩小**）

| 越界 | 位置 | 为什么现在留着 | 什么时候消除 |
|---|---|---|---|
| 功能→功能 | `commands.py` → `report.py` | `/list` 复用日报的读函数（当时刻意：不重复实现） | 日报区块注册表那一步，把读函数归位到内核读层 |
| 内核→功能 | `daemon.py` → `commands.py` | 通道层按字面分流，但内核按名字认识了功能 | 命令注册表那一步 |
| 内核→功能 | `daemon.py` → `watchdog.py` | **形态是好的**：`try/except` 降级加载，失败只记一行日志 | 插件自注册（等第二个插件出现） |
| 内核→功能 | `telegram.py` → `commands.py` | CLI 为了推 `/` 菜单去取命令表 | 把菜单表当参数传进来（方向反转） |

> ⚠️ **白名单是登记事实，不是许可。**
> 新增第 5 条越界边 → 自检**红**；
> 把某一条修好了 → 自检**也红**（提醒你删掉这一行）——
> 免得这份名单变成谎话（同源教训：README「归档不等于可以忘掉」）。

## 四、不变量（照旧，不因平台化而放松）

[`ARCHITECTURE.md`](ARCHITECTURE.md) §十一 的七条判据 = **功能准入门槛**，
一条都不放宽。其中六条现在是靠"硬编码 + 断言"守住的，**改注册表时它们会一起松动**
（逐条分析见 [`PLATFORM-BOUNDARY.md`](PLATFORM-BOUNDARY.md) §4.4）：

| 不变量 | 现在谁在守 |
|---|---|
| agent 只增、不删 | `selftest.py` 的「写入端不含删除能力」+「v4 路径不调用 `reminders.delete`」 |
| 读不到 ≠ 没有 | `report.py` / `commands.py` 的失败标志 + 对应断言 |
| 类型由符号声明，不猜 | `routes.py` 的拒绝路径 + 「v4 删除的判据：不许把"猜"请回来」 |
| agent 无状态、不构成闭环 | `journal` 只追加；**目前没有自动断言，只有文档** ← 最薄的一处 |
| 测试环境由调用方声明 | `PDCA_JOURNAL_DIR` / `PDCA_SUPPRESS_SEND` / `Intake(testing=True)` |
| 附加组件不得拖垮收件 | `watchdog` 四处 `except` + `daemon` 降级加载 |

## 五、journal schema（数据轴 —— 本项目真正需要"向后兼容"的地方）

代码可以回滚，**已经写下的 `.jsonl` 不能**。所以数据这一侧的规矩比代码更严：

| 动作 | 版本影响 |
|---|---|
| 加一个新事件名 | MINOR（第 2 位） |
| 给已有事件**加字段** | MINOR |
| 改已有字段的语义 / 删字段 / 改事件名 | **MAJOR（第 1 位）**，且要在本文写下新旧对照 |

**已经发生过一次**：`a1e4733`（2026-10-05）给 `event_added` 加了重复规则字段，
而 `journal.append(event, **fields)`（`journal.py:135-161`）对字段**不校验、不报错、不留痕**。

⚠️ **已知的第二处登记点**（待收口）：事件名在 `journal.py:108-116`（`EV_*` 常量）
与 `intake.py:82-89`（`_LOG_FUNCS` 的裸字面量）各写一遍，
且 `intake.py:340-342` 取不到时**静默 `return`** —— 漏登记 = 一条记录都不写、没人知道。

## 六、版本怎么加

**单一来源**：`VERSION` 文件（三名整数）。`CHANGELOG.md` 顶部引它，自检断言两者一致 ——
写在两处的版本号一定有一处是错的。

| 位 | 什么时候 +1（任一条命中就进这一位） |
|---|---|
| **第 1 位** MAJOR | ① 输入语言变了（§一 第 ① 层）② 同一输入落点变了 ③ journal/config 需要数据迁移（§五）④ 内核 ABI 或 §二 边界不兼容 |
| **第 2 位** MINOR | 新增功能或新增事件/字段，且上面四条一条都不命中 |
| **第 3 位** PATCH | 修 bug，完全不改契约 |

规矩（[SemVer 2.0.0](https://semver.org/)）：不许前导零；每位**各自**数值递增
（`1.9.0 → 1.10.0`，不是 `2.0.0`）；**发布过的版本内容不得再改**；
`v1.2.3` 是 tag 名，版本号是 `1.2.3`。

**tag 约定**：`vX.Y.Z` 注解 tag 打在"契约发生变化"的那次提交上。

| tag | 含义 |
|---|---|
| `v0.9.0` | 契约前基线（2026-10-05）。按 SemVer 规则 4，此前全部属于 `0.y.z` 初始开发期 |
| `v1.0.0` | **契约第一次被写下来**。此前没有声明过公开 API，所以不追认历史编号 |

**架构代号与版本号并存**：`v1.0 / v4.0 / v4.1` 这些**历史里程碑保留**在 CHANGELOG 里当名字用
（它们有信息量），但不再递增。

## 七、这份契约怎么改

| 改动 | 要走的手续 |
|---|---|
| 加一个**功能** | 在 §二 登记它属于"功能"；若它引入新的输入符号或落点 → 同时进 MINOR |
| 加一个**内核模块** | §二 + 自检的分类表；内核之间可以互相 import |
| 动 §一 的任一层 | **MAJOR** + 改 `VERSION` + 在 `CHANGELOG.md` 写下"你要重学什么" |
| 消除一条 §三 越界 | 删掉那一行（自检会提醒你）+ 记 CHANGELOG |

守着这份契约的断言在 `src/selftest.py` 的「内核契约（平台边界与版本）」一节 ——
**改契约必须同时改断言，否则自检不让你过。** 这正是它和一份普通文档的区别。
