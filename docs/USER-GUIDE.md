# 使用说明（使用者版）

> 这份是给**使用者**看的：只讲你每天怎么用、说错了怎么收拾。
> 开发者 / 运维请看 [README.md](../README.md) 与 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 一、一句话总览

你往 Telegram 里的 bot 发一句中文，Mac mini 上的守护进程把它分派到对应的 Apple 应用
（提醒事项 / 日历 / 备忘录）；当天 21:30 再把三处的当前状态汇总成日报推回 Telegram
（Bark 同时推一份，互为冗余）。**你只需要做两件事：**

1. **发消息** —— Telegram 是唯一入口，必须联网；
2. **在 Apple App 里打钩 / 改字 / 删条目** —— 那才是唯一的状态源。

agent 只负责"增"：写进去之后，改和删都在你手里。

## 二、三种类型：各自适合记什么

| 类型 | 去哪 | 适合记什么 | 判据（代码里的真实线索） |
|---|---|---|---|
| **待办** | 提醒事项 | 一件"要做的动作"，有做完 / 没做完，你打钩 | **动作动词出现在开头 8 个字以内**，且正文不超过 40 字。动词表含：交、买、付、寄、发、取、办、写、整理、核对、检查、联系、回复、确认、预约、订、提交、打印、盖章、跟进、催、准备、更新、补、缴… |
| **日程** | 日历 | "某个时间点发生的事" | 含**事件名词**（会、周会、例会、评审、面谈、聚餐、生日、出差、航班、体检、考试、比赛、跑步、健身…），或有**周期表达**（每周一 / 每天 / 每月 5 日 / 每个工作日） |
| **备忘** | 备忘录 | 一条"记下来别忘了"的信息 | 既没有动作动词也没有事件名词；或含「想起、记一下、记下、备忘、灵感、想法、注意」这类词 |

判定的**顺序**本身就是规则（`classify.py`）：① 含「想起 / 记一下」这类词且没有事件名词 → **备忘**；
② 有周期表达（每周一、每天…）→ **日程**；③ 有事件名词 → **日程**（没写时间的会追问你）；
④ 动作动词在开头、且不超 40 字 → **待办**；⑤ 只给了一个时间点、没有别的内容 → **日程**；
⑥ 都判不出 → **问你**（给三个按钮）。

两个容易误会的点：**一条消息 = 一条记录**（代码里没有拆句子的逻辑，一句话塞两件事只会变成一条）；
**时间只是线索不是唯一判据**（`明天交电费` 有时间也是待办，`项目周会` 没时间也还是日程）。

## 三、怎么说最不容易出错

下面这些都可以直接发，箭头右边是它会去哪里：

```
你发：
交电费                        → 待办（提醒事项）
明天交电费                    → 待办（时间写进备注）
上午九点 交电费                → 待办（时间放开头）
周五下午两点项目周会            → 日程（日历）
10月5日上午十点评审            → 日程
每周一交周报                  → 日程（日历里带"每周一"的重复规则）
每天晚上八点跑步                → 日程（每天重复）
想起一件事，荷载要按名称命名      → 备忘（备忘录）
```

规律：

- **待办**要动词打头、句子短；动词不在开头或句子太长，就不往提醒事项里塞（见下面反例）。
- **日程**要"时间 + 事由"一起说，时间写在句首最稳 —— 系统只剥掉句首的时间短语，剩下的才是标题。
- **日程只给事由、不给时间**（比如只发 `项目周会`）→ 会追问一次，多一轮来回，一次说完最省事。
- **周期性事务**进日历：日历有重复规则，提醒事项不支持。想让它出现在打钩清单里，就别用"每周 / 每天"这类词。
- 反例：`这个年代真正要学的是原理和工程思想，至于编码交给AI吧` → 判成**备忘**（动词不在开头、句子长）；
  `给妈妈打个电话` → 判不准 → 给你三个按钮（"给…打电话"不在动词表里）。

时间可以怎么说（`whens.py` 支持的说法）：

- 日期：`今天` `明天` `后天` `大后天` `昨天` `前天`；`周五` `星期五` `礼拜五` `这周五` `下周五` `下下周五`；`10月5日` `10月5号` `10/5` `2026-10-05` `2026年10月5日`
- 时刻：`14:00` `14点` `14点30` `下午两点` `下午2点` `晚上8点半` `早上9点` `中午12点` `凌晨1点`
- 只写时段也认：凌晨 5:00、早上 / 早晨 8:00、上午 9:00、中午 12:00、下午 14:00、傍晚 17:00、晚上 20:00、夜里 21:00
- 不带前缀的"周五"= 最近的将来那个（今天就是周五就算今天）；只写日期、连时段都不写 → **全天**的
  日程，给了时段或具体时刻 → **1 小时**的定时日程（时段按上一行换算成整点）。

## 四、判不准时会发生什么

判不准时**什么都不会写入**，先给你三个按钮，点一下才写。下面是实际的一轮：

```
① 你发：测试Apple- agent稳定性

② 机器回：
🤔 「测试Apple- agent稳定性」我不确定该怎么记 —— 它是哪一种？
　　（选错也没关系，你在对应 App 里改就行）
选一个：[待办] [日程] [备忘]     ← 另一条带按钮的消息，此时还没写进任何 App

③ 你点「日程」（机器先弹一个小提示"收到"），机器回：
🤔 「测试Apple- agent稳定性」像是日程，但没写时间。
　　回一句时间就行（例：上午九点）——
　　我会把它接到这条上，不会另建一条。
　　（要改成待办/备忘，点下面的按钮）
回一句时间就行：[待办] [日程] [备忘]

④ 你回：上午九点

⑤ 机器回：
✅ 已记下（日程）：测试Apple- agent稳定性
　　10月4日 周日 09:00
　　→ 在「日历」里
　　（接在你上一条上，没有另建）
　　（这个时间今天已经过了，我放到了明天 —— 要改就去日历里改）
```

要注意的几点：

- 第一轮的三个按钮点了就写（好用）。**但追问之后的那组按钮点不动**，会回"这条已经处理过了
  （或已过期）。"—— 要补时间就直接**发一句时间**，这条路是通的（已知的小毛病）。
- **补时间只在紧接着的下一句有效**，那一句必须"光秃秃只有一个时间"。接着发带内容的一句
  （比如 `明天交电费`）就是**新的一条**；写成功之后，那条待补充的会作废（不会写进 App，得重新说）。
- 待补充只有一个槽位：新的一句替掉旧的，超过 **24 小时**作废。不用点 Telegram 的"回复"功能，
  直接发就行（系统不看你回复了哪一条）。
- 那个时刻如果今天已经过了，会自动挪到明天，回执末尾多一行说明（例：晚上回 `下午三点` → 明天 15:00）。

## 五、怎么纠错（重点）

先记住一句话：**打钩、改字、删除全部在 Apple App 里做。** agent 只能"增"，不能改也不能删。

| 发现的问题 | 怎么做 |
|---|---|
| 待办做完了 | 在提醒事项里打钩（日报读的就是这个状态） |
| 标题被吃掉、只剩时间（"上午九点"成了标题） | 去日历里改名，或删掉那条，再完整重说一句 |
| 时间落在过去 | 去日历里改时间 |
| 归错类了 | 在对应 App 里删掉，再带上明确的线索词重说一句 |
| 重复建了两条 | 在 App 里删掉多余的那条 |
| 备忘处理完了 | 在备忘录里删掉它 |

**不要再发一句去"覆盖"。** 每条消息都会**新建**一条，系统不会去修改原来那条 —— 它写完也不回读
自己写过的东西来判断。唯一例外是第四节那个"补时间"：紧接着回一个纯时间，才会接到上一条上。

## 六、日报

每天 21:30 推 Telegram（Bark 同时推一份），并存档到 `data/digest/日期.md`。
固定四段、每段都可能不出现，末尾是固定页脚。机器推给你的日报长这样：

```
📋 2026-10-03 复盘

✅ 今日完成 2 件
　勘察表盖章
　交电费

⏳ 未完成 2 件
　跟进竣工报验
　跟进修缮

📅 明日日程 2 项
　14:00 项目周会
　09:00 体检　@市一院

📝 备忘放了 3 天以上，还没处理：
　荷载要按名称命名
　（这个清单来自台账，删掉不会自动消失 —— 暂时请忽略已处理的条目）

──────────────────────────────
做完的在「提醒事项」里打钩 ✓
（发一句给我也行，比如「明天交电费」）
```

- 待办全部完成时，"未完成"那段变成 `🎉 今天的待办全部完成了`；提醒事项里一条都没有时，会说
  `（提醒事项里还没有条目 —— 发一句给我就行）`。
- 某个来源读不到时，会出现 `⚠️ 以下来源读取失败，本份可能不完整：` 并写明是哪一处、缺什么权限 ——
  它不会把"读不到"说成"没有"。
- "今日完成 / 未完成"读的是提醒事项列表里的**全部条目**，没有按日期过滤：已完成的旧条目会一直在
  "完成"里，除非你在 App 里删掉；未完成的会一直留在"未完成"里。

## 七、边界与限制（如实）

- **必须联网。** Telegram 是唯一入口，没网就记不了。退路是直接在三个 App 里手动记 —— agent 没有
  自己的副本，不会跟你"坚持己见"。
- **agent 只增，不改不删。** 写错了只能你自己去 App 里改；**周期性事务放日历**（提醒事项的脚本
  接口不支持重复）。
- **提醒事项不设到期日。** 时间只写在备注里（形如 `pdca:xxxx · 10-04 09:00`），不会弹到期通知、
  不会变红，要靠日报和你自己看。
- **备忘放 3 天以上会在日报里被提醒。** 但"你在备忘录里删掉它、日报就不再提醒"这一步**目前还没接上**：
  代码里没有任何定时任务去读备忘录做差集，日报的提醒读的是 agent 自己的台账。所以删掉之后，
  日报可能还会提醒它，忽略那一行就行。（日报那一行现在也如实这么写了 ——
  它之前写的是"删掉即可，之后不再提醒"，那是**未实现的承诺**，已改掉。）
- **补时间只在紧接着的下一句有效**，只有一个槽位，超过 24 小时作废。
- **你明确说了日期就不会顺延。** 只有"只说了时刻、且那个时刻今天已过"才会挪到明天。像晚上发
  `今天上午九点 体检`，日程就落在今天 09:00（已经过去）。
- **一条消息 = 一条记录**，没有"再说一次来修改"的通道。自然语言解析一定有误差；纠偏成本低 ——
  去 App 里改，或删掉重说。

## 八、出问题怎么办

**守护还在不在跑？** 最直接的办法：发一句话给 bot，看有没有回执。没回执时，在终端里：

```bash
cd /Users/carl-mini/dev/siri-carl/pdca
bash deploy/install_launchd.sh status      # 要修就：bash deploy/install_launchd.sh restart
```

看 `com.carl.pdca.daemon` 那一段，要有 `pid = 数字`（只有一行 `state` 不算数）。
`com.carl.pdca.report` 平时不跑是正常的 —— 它是定时任务。

**日报没收到，按顺序查：** ① `status` 里 report 任务的 `last exit code`（0 才好；推送失败会是 3）；
② `logs/report.out.log` 和 `logs/report.err.log` 的最后几行；③ `data/digest/今天日期.md` 生成了没有 ——
生成了说明日报算出来了，是**推送**没到（两个通道都失败时，日志里会打印"所有通道都推送失败"）；
④ 日报里出现 `⚠️ 以下来源读取失败` → 是授权问题：系统设置 → 隐私与安全性 → 自动化 → 终端 →
勾选「提醒事项」「日历」「备忘录」；⑤ 只想看日报长什么样、不推送：`python3 src/report.py --no-push`；
⑥ 一次只读体检：`bash deploy/install_launchd.sh doctor`。

**刚更新过代码**：守护是常驻进程，改了代码要 `restart` 一次才会用上新逻辑。

**任何一环挂掉的后果**：agent 不保存"我做过什么"的记忆用于决策，每次都从 Apple 应用现读真相，
所以挂掉只损失"一次自动整理"，不会造成数据不一致 —— 你先在 App 里手动记，等它恢复。
