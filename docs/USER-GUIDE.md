## 一、一句话总览

你往 Telegram 里的 bot 发一句中文，Mac mini 上的守护进程把它写进对应的 Apple 应用
（提醒事项 / 日历 / 备忘录）；当天 21:30 再把三处的当前状态汇总成日报推回 Telegram
（Bark 同时推一份，互为冗余）。**你只需要做两件事：**

1. **发消息** —— Telegram 是唯一入口，必须联网；
2. **在 Apple App 里打钩 / 改字 / 删条目** —— 那才是唯一的状态源。

agent 只负责"增"：写进去之后，改和删都在你手里。

> **最重要的一条**：类型不靠猜，靠你**在行首写符号**声明。
> 忘打符号不会报错 —— 它会按默认落进「提醒事项」。

## 二、符号表（唯一的判据）

| 你写的 | 去哪 | 符号必备？ |
|---|---|---|
| `交电费` | 提醒事项（待办） | **不用打** —— 最高频的动作零成本 |
| `# 学原理比学语法重要` | 备忘录（备忘） | 要打 |
| `@周五下午两点 项目周会` | 日历（日程） | 要打，且时间必须能认出来 |
| `!交电费` | 提醒事项（带**旗标**） | 要打（2026-10-07 新增）|
| `!!交电费` | 提醒事项（旗标 + **高优先级**）| 要打 |
| `- [ ] 交电费` | 提醒事项 | 可用（你原来 `-` 的习惯不用全改） |
| `/list` | **哪里都不去**（只读） | 要打 —— 看现在的待办与日程，见第五节 |

符号的容错（下面这些写法实测都认）：

- 全角也算：`＃` `＠`；
- 别的前缀符号：`*` `•` `·` `・` 当**备忘**；`-` `–` `—` `−` `‐` 当**待办**；
- 复选框：`[ ]` `[x]` `[X]` `[✓]` `[✔]`（半角全角都认）。

**代价要记住**：裸输入默认进提醒事项，所以一段"感慨"不打 `#` 就会进你的打钩清单。
判错的代价是不对称的 —— 这个默认是**你选的**，换来的是"最高频的动作零成本"。

## 三、三种类型：各自适合记什么

| 类型 | 去哪 | 适合记什么 | 不适合 |
|---|---|---|---|
| **待办** | 提醒事项 | 一件"要做的动作"，有做完 / 没做完，你打钩 | 一大段想法（那是备忘）|
| **日程** | 日历 | "某个时间点发生的事"，尤其是**周期性**的 | 没有时间点的事（`@` 会报错）|
| **备忘** | 备忘录 | 一条"记下来别忘了"的信息 | 需要打钩的动作 |

两个容易误会的点：

- **一条消息 = 一条记录。** 代码里没有拆句子的逻辑，一句话塞两件事只会变成一条。
- **时间不改变归属。** `明天交电费` 仍然是**待办**（时间进备注）；
  要进日历，必须打 `@`。
- **周期性的日程会到点提醒你**（2026-10-07 起）：`@每天8:35 检查待办` 会真在
  8:35 弹一条 —— 这是待办做不到的（提醒事项不支持重复）。
  **一次性日程不弹提醒**（只给带重复的加），所以别拿它当闹钟用。
- **待办的时间是"真的到期日"**（2026-10-07 起）：`明天交电费` 会在提醒事项里
  变红、进"今天/已编排"；给了具体时刻的**到点会弹一次**。
  待办落在提醒事项的**默认列表**里 —— 想换列表就改提醒事项设置里的默认列表。

## 四、时间可以怎么说（只有 `@` 需要）

- 日期：`今天` `明天` `后天` `大后天`；`周五` `星期五` `礼拜五` `这周五` `下周五`；
  `10月5日` `10月5号` `10/5` `2026-10-05` `2026年10月5日`
- 时刻：`14:00` `14点` `14点30` `下午两点` `下午2点` `晚上8点半` `早上9点` `凌晨1点`
- **只写时段也认**，按这张表换算：凌晨 5:00 · 早上 8:00 · 早晨 8:00 · 上午 9:00 ·
  中午 12:00 · 下午 14:00 · 傍晚 17:00 · 晚上 20:00 · 夜里 21:00
- 重复：`@每周一 交周报` `@每天八点 跑步` `@每月5日 交房租` `@每个工作日 站会`
  —— 周期表达**可以带时刻**：`@每周一 早上九点 站会` 会落成"每周一 09:00"的重复日程；
  不带时刻就是**全天**的重复日程。
  **重复日程会在每一次发生的那天出现**（`/list` 与日报里都带 `（每天）`／`（每周一）`
  这样的标记）；只有"每月第二个周二"这类日历里的高级自定义规则还算不出来 ——
  那种情况它只在首次那天出现，不会假装。
- **只写日期、不写时刻 → 整天**（日历里是"全天"）；
  写了时段或具体时刻 → **1 小时**的定时日程。
  ⚠️ 只写"下午"这种时段也算 14:00（按上表），**不是**整天。
- 标题是"剥掉句首时间短语之后剩下的部分" —— 所以时间写在句首最稳。

`@` 后面**必须**有能认出来的时间，而且**必须**有事由。缺哪一样都报错，且**一个字都不写**：

```
你发：@下辈子 交电费     → ❌ 没记成：这条日程的时间我认不出来
你发：@上午九点          → ❌ 没记成：这条日程只有时间、没有写是什么事
```

不做的三件事（都是刻意的）：**不退回当备忘写**（那是替你改主意）、
**不追问"什么时候？"**（那要跨消息记住"在等什么"）、
**不用默认时刻硬塞**（那会静默写出一条错时间的日程）。

## 五、它回你什么（回执）

写成功了长这样（**2026-10-07 起**：待办的时间会落成原生到期日）：

```
✅ 已记下（待办）：交电费
　　10月8日 周四（全天 · 不弹提醒）
　　→ 在「提醒事项」里

✅ 已记下（待办）：交电费
　　10月8日 周四 14:00（到点提醒） · 已加旗标 · 高优先级
　　→ 在「提醒事项」里
```

- 正文**超过 20 字会截断**（写进 App 的是全文，回执只是让你认出是哪条）。
- 日程会显示算出来的时间（如 `10月9日 周五 14:00`）；
  **待办的时间会变成真的到期日** —— 它会在提醒事项里变红、进"今天/已编排"，
  给了具体时刻的**到点还会弹一下**（回执里写"到点提醒"）。
  只有"说了时刻、没说日期"（如 `交电费 8:35`）才退回备注。
- **重复日程会多一句「到点会提醒」**（它真的会弹）；一次性日程没有这句，也不弹。
- 只说了时刻、而那个时刻今天已经过了 → 自动挪到明天，并多一行说明。

写失败了会说清原因并给出路（`❌ 没记成：…`），并且**一个字都不写**。

**音量分档**（2026-10-04 起）：回执与启动通知**静音**（不响不震，横幅和未读角标仍在）；
**失败**和 **21:30 的日报**会响 —— 所以它"叮"一声，就是有值得看的东西。

**回执发不出去时会自动重试**（等 5 秒、再等 15 秒）。极少数情况下
（网络真的断了）你什么都收不到，但条目**已经写进去了** ——
别急着重发，当晚 21:30 的日报会把它读出来。

**发语音 / 图片 / 文件**：它读不了，会明确回你一句"我只认文字消息"
（以前是完全没反应，看起来像它死了）。

### 想看现在有什么：发 `/list`

这是唯一**只读**的输入 —— 一个字都不写：

```
📋 现在 10月4日 周日 21:40

⏳ 待办 3 件
　交电费
　跟进竣工报验
　制作一个agent学习视频

📅 今天还有 1 项
　22:30 夜跑
📅 明天 2 项
　14:00 项目周会　@会议室
　全天 国庆值班
```

- 别名（完全一样）：`/ls` `/today` `/now` `/todo` `/列表` `/待办` `/日程`；大小写不敏感。
- **在 Telegram 里打 `/` 会自动补全**（菜单里就这一条），不用记全名。
- **必须带斜杠**：`list` 不带斜杠就是一条**待办**（"list" 可以是你要买的东西）——
  判据和别的输入一样是行首字符，不是词。
- 待办只列**没打钩的**；日程列"今天还没结束的 + 明天全部"。
  全天日程写成 `全天`，不会显示成 `00:00`（那看起来像半夜有安排）。
- 一屏最多 15 条，超了会说 `…还有 N 条`。
- 某处读不到时**如实写"读不到"**，绝不把"读不到"说成"没有"。
- 这条命令**不进 journal**（你的内容留痕）：它是读操作，不产生要复盘的内容。

## 六、怎么纠错（重点）

先记住一句话：**打钩、改字、删除全部在 Apple App 里做。** agent 只能"增"，不能改也不能删。

| 发现的问题 | 怎么做 |
|---|---|
| 待办做完了 | 在提醒事项里打钩（日报读的就是这个状态）|
| 归错类了 | 在对应 App 里删掉，再**带上正确的符号**重说一句 |
| 标题被吃掉、只剩时间 | 去日历里改名，或删掉那条，再完整重说一句 |
| 时间不对 | 去日历里改时间 |
| 重复建了两条 | 在 App 里删掉多余的那条 |
| 备忘处理完了 | 在备忘录里删掉它 —— 日报**真的**会因此不再提醒（见第七节）|

**没有再发一句去"覆盖"这条路。** 每条消息都会**新建**一条：系统不提供"改"，
写完也不回读自己写过的东西来判断。

> v1 曾有"紧接着回一个纯时间 → 接到上一条上"的补全通道，**已整体删除**。
> 它要跨消息记住"在等什么"，贡献过两次真实故障。缺什么，就带符号重说一句完整的。

## 七、日报

每天 21:30 推 Telegram（Bark 同时推一份），并存档到 `data/digest/日期.md`。
段落固定、每段都可能不出现，末尾是固定页脚：

```
📋 2026-10-03 复盘

🕘 生成于 21:30（数据截至同一时刻）

✅ 今日完成 2 件
　勘察表盖章
　交电费

⏳ 未完成 1 件
　跟进竣工报验

📅 明日日程 1 项
　14:00 项目周会

📝 备忘放了 3 天以上，还没处理：
　荷载要按名称命名
　（处理完在备忘录里删掉即可，之后不再提醒）

──────────────────────────────
做完的在「提醒事项」里打钩 ✓
想加一条就直接发：交电费 · # 想法 · @周五两点 周会
```

- 待办全部完成时，"未完成"那段变成 `🎉 今天的待办全部完成了`；
  提醒事项里一条都没有时，会说 `（提醒事项里还没有条目 —— 发一句给我就行）`。
- 某个来源读不到时会出现 `⚠️ 以下来源读取失败，本份可能不完整：` 并写明是哪一处 ——
  **它不会把"读不到"说成"没有"**。
- **备忘放了 3 天以上**会单列一段。你在备忘录里删掉它之后，日报会**真的**不再提醒它 ——
  它先查自己的台账，再做一次**只读快照差集**确认"这条还在不在"。
- 「今日完成 / 未完成」读的是提醒事项列表里的**全部条目**，没有按日期过滤：
  已完成的旧条目会一直在"完成"里，除非你在 App 里删掉。
- **日报没跑，会有人发现**：守护进程里带了个看门狗，当天 **23:30** 还没有投递成功的读数，
  就推一条告警（标题 `⚠️ 今天的日报没送到`，里面附手动补跑命令），每天最多一次。
- 比计划时间早/晚跑出来的日报，开头会多一行说明
  （`⚠️ 比计划（21:30）晚 N 分钟 —— 多半是机器在计划时间没醒，唤醒后才补跑`）。

## 八、边界与限制（如实）

- **必须联网。** Telegram 是唯一入口，没网就记不了。退路是直接在三个 App 里手动记 ——
  agent 没有自己的副本，不会跟你"坚持己见"。
- **agent 只增，不改不删。** 写错了只能你自己去 App 里改；
  **周期性事务放日历**（提醒事项的脚本接口不支持重复）。
- **日程落在日历「个人」**（`config.json` 的 `calendar_name`）。
  **换日历是人工操作** —— 改这个值就行（改完不用重启守护）；
  项目**不会**自己猜你要落哪个。⚠️ 日历分账户：落在「我的 Mac 上」的日历
  **不进 iCloud**，手机上永远看不到（见 [`APPLE-FACTS.md`](APPLE-FACTS.md) §2.4）。
- **日报和 `/list` 读`全部`列出来的日历**（`calendar_read_names`，现在是「个人」+「工作」）——
  这样你的日程分散在两个日历时，另一个不会"看不见"。
  **写只有一个落点，读可以多个**：前者是"每个事实只有一个写入者"，后者是"看不见 ≠ 没有"。
- **待办的时间是原生到期日**（2026-10-07 起）：`明天交电费` 会在提醒事项里变红、
  进"今天/已编排"；给了具体时刻的**到点弹一次**。只有"说了时刻、没说日期"
  （`交电费 8:35`）落不成日期，才退回备注 —— 回执里会注明。
- **待办落在提醒事项的默认列表**（不再是我们自建的 `PDCA` 列表）——
  想换就改提醒事项设置里的默认列表，项目跟着走。
  （2026-10-05 之前备注里还有一串 `pdca:xxxx` 去重键，那是 v1 的遗留，已去掉。）
- **类型靠符号，不靠语义。** 不打符号就是待办；系统不猜你的意图（这是刻意的）。
- **一条消息 = 一条记录**，没有"再说一次来修改"的通道。
- **图片 / 语音 / 文件不会被记录**，只会得到一句"我只认文字"。
- **回执可能迟到。** 网络抖动时会重试（5s / 15s）；真发不出去时，条目仍然写进去了。
- **改了代码要重启守护**：它是常驻进程，不重启就还在跑旧逻辑。

## 九、出问题怎么办

**守护还在不在跑？** 最直接的办法：发一句话给 bot，看有没有回执
（回执是**静音**的，别等声音 —— 看聊天窗口）。没回执时，在终端里：

```bash
cd /path/to/telegram-apple-reminders    # 换成你 clone 的位置
bash deploy/install_launchd.sh status      # 要修就：bash deploy/install_launchd.sh restart
```

看 `io.github.carlapple2025.pdca.daemon` 那一段，要有 `pid = 数字`（只有一行 `state` 不算数）。
`io.github.carlapple2025.pdca.report` 平时不跑是正常的 —— 它是定时任务。

> ⚠️ 实测踩到过：`restart` 在**受限的执行环境**里会
> `Bootstrap failed: 5: Input/output error` —— bootout 成功、bootstrap 失败，
> 结果是守护**没在跑**。换到普通终端里跑同一条命令即可。

**日报没收到，按顺序查：** ① `status` 里 report 任务的 `last exit code`（0 才好；推送失败会是 3）；
② `logs/report.out.log` 和 `logs/report.err.log` 的最后几行；
③ `data/digest/今天日期.md` 生成了没有 —— 生成了说明日报算出来了，是**推送**没到；
④ 日报里出现 `⚠️ 以下来源读取失败` → 是授权问题：系统设置 → 隐私与安全性 →
自动化 → 终端 → 勾选「提醒事项」「日历」「备忘录」；
⑤ 只想看日报长什么样、不推送：`python3 src/report.py --no-push`；
⑥ 一次只读体检：`bash deploy/install_launchd.sh doctor`。

**刚更新过代码**：守护是常驻进程，改了代码要 `restart` 一次才会用上新逻辑。

**任何一环挂掉的后果**：agent 不保存"我做过什么"的记忆用于决策，每次都从 Apple 应用现读真相，
所以挂掉只损失"一次自动整理"，不会造成数据不一致 —— 你先在 App 里手动记，等它恢复。
